# screen-toggle 架构

当前实现采用 Rust、windows-rs 与 Win32 API。领域逻辑作为库组织，桌面程序负责窗口、消息循环和系统集成；默认绘制路径为 GDI/GDI+，Direct2D 是可选 feature。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `main.rs` | 声明桌面模块，进入应用并呈现启动错误 |
| `app.rs` | 解析参数、单实例、托盘、热键、设置保存、UI 与后台协调 |
| `panel.rs` | 设置窗口、布局、滚动、原生控件状态与缓冲绘制 |
| `about.rs` / `theme.rs` | 无提示音的关于窗口；统一主题配色与系统偏好 |
| `engine.rs` | 设备模型、后端接口、熄屏/恢复事务、取消代际、写入确认与恢复记录 |
| `native.rs` | 真实 DDC/CI、WMI、HDR 扫描、执行与回读 |
| `config.rs` | 配置序列化、合法性校验及旧配置迁移 |
| `storage.rs` | 临时文件写入与原子替换 |
| `schedule.rs` | 按日期去重的每日定时，手动操作后 10 分钟让步 |
| `remote.rs` | 获取本机正在被远程控制的证据，供自动光标策略使用 |
| `win.rs` / `antialias.rs` / `d2d.rs` | Win32 辅助、GDI+ 几何抗锯齿和可选 Direct2D 绘制 |
| `lib.rs` | 导出配置、调度、存储、引擎与 Windows 后端，支持领域单元测试 |

`checks/` 是开发验证工具，`rust/examples/` 是诊断入口。它们不属于运行发布 EXE 时的依赖。

## 线程与状态

UI 状态只在窗口线程访问。热键、托盘和设置操作转成命令，硬件工作线程顺序处理命令；配置保存也通过后台处理。阻塞式 DDC/CI、WMI 和文件 I/O 不直接放进窗口绘制回调。

每次切换更新 generation。后台在阻塞调用后重新检查代际，过时操作停止继续改变状态；已经发出的设备调用仍需结束、汇合，保留后续恢复所需信息。不能通过丢弃线程来取消硬件调用。

同一批次内，不同外接屏使用各自的 scoped worker，本地 WMI 在协调线程上执行；设备之间并行，同一设备的读写保持顺序。WMI 的 COM 对象不跨线程搬运。所有 worker 汇合后才结束该批次，HDR 阶段与亮度阶段之间保留屏障。

## 熄屏链路

1. UI 接收热键、面板或托盘请求，发布新的目标状态和 generation。
2. 引擎按设置决定黑窗呈现顺序。默认先呈现黑窗和光标策略，再执行硬件调光。
3. 扫描所需设备，读取真实原值；硬件改动前将恢复基线持久保存到 journal。
4. 按需处理 HDR，再并行调节亮度。每路写入后精确回读，形成独立结果。
5. 返回当前状态与警告。硬件失败时保留对应恢复信息，不能把软件黑窗成功当成硬件调光成功。

淡入策略由 UI 定时器推进黑窗透明度；硬件链路仍遵守设备顺序与恢复保护。

## 普通亮屏链路

1. 读取未完成恢复记录，按稳定设备身份重新匹配当前设备。
2. 如有 HDR 恢复，先完成该阶段并确认结果。
3. 并行写回各设备原亮度。
4. 默认 Ready 模式下，全部请求的亮度写入成功后派发一次 UI 操作，同时撤黑窗、恢复光标；最后一路继续回读。
5. 汇合精确回读结果，仅清除确认成功的记录；失败、取消或 UI 拒绝的项保留供下次恢复。

提前呈现的计数分母是全部请求设备。某个请求未授权、线程未建立或写入失败，都不能因为没有进入成功列表而被遗漏。UI 也会检查 generation，避免旧请求将新的熄屏状态撤掉。

固定延迟模式走完整恢复确认路径，再额外等待 `delay_ms`，最后恢复画面。退出也走恢复路径；恢复记录损坏时保留原文件并报告错误，不猜测原始亮度。

## 调光耗时检测

检测先执行一次压暗，再执行一次恢复，两个阶段依次进行。每个阶段内部跨设备并行。

测量配置不创建可见黑窗，不切换系统光标。结果取压暗与恢复两阶段中较慢的硬件批次确认时间，保存上限为 500 ms。该时间包含写入与精确回读；扫描、恢复记录落盘和 UI 排队不属于这个硬件耗时字段。

检测恢复可以在拓扑、身份和资源仍有效且未涉及 HDR 时一次性复用本轮快照；不符合条件时重新准备恢复。缓存 WMI 路径与方法元数据可以减少准备时间，真实亮度仍需读取。

## 设置与界面

默认数据位于 `%APPDATA%\ScreenOffGuard\`，保留目录名以兼容已有配置。配置使用 `settings.json`，未完成的硬件恢复使用 `recovery.json`。

设置保存与硬件执行相互独立。用户输入先保留草稿，通过校验后提交保存；错误输入或保存失败不应被默认值静默覆盖。热键先尝试注册，新组合失败时保留原组合。

面板以统一缓冲提交页面视觉，保留原生控件的输入、焦点和可访问语义。布局批量更新同父窗口子控件，避免拖动调整大小时各控件依次擦除。主题由集中配色管理，切换时保留输入草稿、选区和滚动位置。

“开机静默启动”在当前用户 Run 注册命令中加入 `--silent`。普通手动启动显示设置，静默启动驻留托盘；已有实例时仍按这两个入口的意图处理。

## 远控与设备边界

光标自动模式依据本机正在被控制的会话证据。远控软件进程常驻、在线心跳或本机控制别的设备，均不能证明本机正在被控制。缺少可靠证据时按未连接处理。

Windows RDP 使用系统会话标志；第三方适配需要各版本的真实连接/断开验证。UU 私有 IPC 已禁用，RustDesk 和 ToDesk 适配不能由代码存在推断为全面实测通过。

DDC/CI、WMI 和 HDR 能力取决于设备、驱动及连接路径。设备测试入口提供 `--restrict-id` 限定完整设备身份，在调用硬件 API 前执行筛选；诊断程序使用前仍需检查其覆盖范围。
