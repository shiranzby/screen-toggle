## 窗口与输入

本发布构建的隔离消息回归共8组：选屏4组、两套热键1组、启动/滚动/关于3组。覆盖保存、取消、重启、零选择、断连不回退、11条显示记录分页、同行开关独立性、键鼠名称与冲突、手动/静默启动、浅深主题、关于作者及仓库入口。浅深面板和关于截图已目视核对；测试不主动打开外部浏览器，链接目标由固定常量和控件文字核验。

同源上一候选的真实 Type-C 侧键双击已由用户操作通过；其后新增黑屏亮屏门禁在 Type-C 两个小区域上显式验证，区域空隙/窗外/hidden拒绝。该区域探针没有输入或调光，不当成人工双击到完整亮屏的验收。本次没有新增连续拖边、Narrator、所有输入法或全部桌面布局验收。

## 已知边界

- 当前硬件样本只有 Type-C；真实 HDR 故障、热插、睡眠/登录恢复、其它设备组合需继续验证。
- 第三方远控自动识别未完整闭环，UU 私有 IPC 保持禁用；显式“始终保留”可避免自动识别不确定性。
- 当前提供软件黑窗/背光压暗，不是系统锁屏、断电或睡眠；捕获排除效果依赖 Windows 与捕获路径。
- 通用亮度滑块、校准、profiles、通用 VCP、SDR 白级/Gamma/ALS 均未在本版实现，见[规划](TWINKLE_TRAY_COMPARISON.md)。

## 复核

`checks/build_release.ps1` 执行构建门槛。`test_display_selection_ui.py`、`test_desktop_mouse_ui.py`、`test_startup_panel_polish.py` 使用模拟后端和 Type-C 隔离窗口；`test_selected_display_native.py` 会实际调节 Type-C，先检查其设备白名单。`measure_resources.py` 原有完整面板实验不应直接在工作屏运行；本版只托盘资源采样保存在汇总JSON。

开发工具可以安装 `checks/requirements.txt` 中的 Pillow，运行发布程序不需要 Python。真实硬件测试失败时保留恢复记录、正常恢复并等待线程结束，不能强杀可能恢复中的进程。历史版本源码可按对应标签读取，不以当前编译结果替旧版本的硬件行为背书。
