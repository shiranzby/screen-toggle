# 亮度恢复修复与可选桌面鼠标手势

v0.4.0 包含以下恢复和输入修复。当前发布哈希与验证见[VALIDATION](VALIDATION.md)，选屏与黑屏亮屏手势见[DISPLAY_SELECTION](DISPLAY_SELECTION.md)。本文中的 91C、F756 与旧测试数量属于开发阶段证据，不冒充 v0.4.0 的新实测。

## 恢复链路

- HDR 改变后重新取得显示器资源，按 journal 设备身份重新绑定。亮度目标始终使用熄屏前持久保存的数值，不把当前压暗值采成新的基线。
- HDR 尚未恢复成功时，保留依赖它的亮度基线；下一次 HDR 重试即使重置亮度，也能再次写回原值。
- 普通亮屏只重新绑定资源和 WMI 方法路径，省去恢复前重复读取 DDC/WMI 亮度。所有写入后仍精确回读。
- 仅失败恢复允许一次重新绑定重试，正常路径只有一遍；重试失败继续保留记录。写入 ACK 的快速显示路径保持，回读和失败重试在后端完成。
- 保存/读取恢复记录时拒绝空身份、重复身份和无效亮度范围。启动时规范化配置目录身份，防止同一目录的路径别名绕过单实例。

模拟反例已覆盖 HDR 使旧句柄失效、HDR 失败后亮度基线不能提前清除、临时失败同一次亮屏恢复、无 HDR 正常路径只准备一次。失败基线反例在修复前确实失败；修复后通过。

Type-C 单设备、各三轮、同一观察入口与原 v0.3.0 源码对照：

| 中位数 | 原链路 | 修复链路 |
| --- | ---: | ---: |
| 引擎开始到全部写入返回的 ACK | 106.9 ms | 55.2 ms |
| 引擎完整亮屏处理 | 159 ms | 110 ms |
| 硬件批次（含精确回读） | 104 ms | 106 ms |

每轮按设备身份核对原亮度恢复一致，无残留恢复记录。此测试没有窗口、系统光标、WMI、HDR 或 HDMI 操作；使用同源诊断构建，ACK 不等于真实界面或物理面板响应。省下的是恢复前的重复采样，硬件本身没有因修改计时口径变快。真实 HDR 故障和其它屏幕组合仍需实机验证。

## 桌面鼠标手势

设置分为两组，点击各自录入按钮后直接按键盘组合或鼠标按键：

| 范围 | 默认热键 | 双击触发 | 启用方式 |
| --- | --- | --- | --- |
| 全局触发 | Ctrl + Alt + S | 默认关闭；开启后连续按两次 | 沿用现有全局热键 |
| 桌面触发 | 鼠标侧键 1 | 默认开启，可关闭为单次触发 | 独立开关，默认关闭 |

支持鼠标左键、鼠标右键、鼠标中键（滚轮按下）、鼠标侧键 1/2，也支持 Ctrl/Alt/Shift/Win 修饰键组合。键盘组合沿用原校验规则。两组热键与双击选项独立保存，启用桌面触发时拒绝与全局组合相同，避免一次操作触发两次。录入期间暂停切换；Esc 取消、冲突保留原组合。滚轮滚动不是中键按下，不作为按键录入。

桌面鼠标触发要求实际点击位于合格 Explorer 桌面空白处，排除图标和其它窗口；桌面键盘触发还要求前台处于桌面。双击模式使用 Windows 的双击时间，鼠标还检查同屏同窗口与距离。拖动、模拟注入、过期事件、长按重复及不同按键不能拼成双击。三连击只切换一次；关闭双击后，单次完整按下/抬起即可触发。全局鼠标按键按其全局范围生效，使用左键、右键等常用按键会影响日常操作，应按需要选择侧键或修饰键组合。

监听和桌面命中检查使用独立线程，不在鼠标钩子中执行无障碍调用或调光，不吞掉鼠标事件。关闭选项后卸载监听。黑窗存在时按实际窗口遮挡关系检查下层桌面。

**酷呆桌面 Coodesker 接管的区域暂停触发，键盘热键仍可使用。** 该软件当前使用整块自绘桌面，标准窗口与无障碍接口无法可靠提供抽屉边界。按用户选择，未知区域拒绝触发，避免把抽屉误当空白；没有使用私有 IPC 或解析其二进制缓存。侧键本身也可避免与其它软件的左键双击手势重叠。

设置保存、按键选择、重启、监听生命周期和状态机分别验证。用户已在 Type-C 的普通 Explorer 桌面空白处完成真实侧键 2 双击，物理输入到触发消息接收通过；该诊断不调光。其它桌面布局、远控鼠标事件以及这次物理手势到实际熄亮屏的完整链路仍未实测。

## 桌面命中检查修正

用户反馈酷呆退出后仍不能触发，因此重新打开桌面识别验收。旧候选依赖 UI Automation 每次枚举全部图标矩形：本机 177 个图标的查询约 130–191 ms，连续输入排队可能超过 250 ms 事件有效期；部分查询环境还会把真实桌面返回为 Pane 与空子树，导致正向识别失败。此前设置保存和监听生命周期通过，不能证明桌面命中链路真实可用。

已改为对确认属于 Explorer 的真实桌面列表执行 MSAA 单点命中：校验进程、桌面宿主、列表角色和原生图标数量，只有明确的 CHILDID_SELF 才允许空白；图标子项和未知结果拒绝。调用仍在独立验证线程，保留超时取消、事件新鲜度、图标排除和前后实际遮挡复核；酷呆等未知自绘桌面不会因“空子树”而放行。

第二个真实反例是按侧键带来的 3–11 像素自然位移被当成拖动。辅助鼠标键（右、中、侧键）的按下/抬起和双击配对距离现在至少容许 16 像素；左键保留系统拖动阈值。大范围拖动、跨屏、跨窗口和非空白端点仍拒绝。用户这次自然侧键双击两次命中分别耗时约 29 ms 和 3 ms，第二击产生触发消息；独立只读命中探针的三个图标均拒绝、两个空白均接受，约 0.2–3 ms。两种耗时分别是输入验证和单点探针，不是显示器调光耗时。

## WMI 实例路径与启动恢复

轻量恢复的 `SELECT InstanceName ...` 在本机返回了空 `__PATH`，后续 `GetObject("")` 取不到屏幕实例，造成 `0x80041002` 和待恢复记录残留。只读反例先失败，再为 ExecQuery 增加 `WBEM_FLAG_ENSURE_LOCATABLE`，并在缓存前拒绝空的亮度/方法实例路径。[微软官方说明](https://learn.microsoft.com/en-us/windows/win32/api/wbemcli/nf-wbemcli-iwbemservices-execquery)确认该标志用于保证系统路径属性可用；保留精简查询，正常恢复没有新增原亮度采样。

另一本机 provider 兼容点是 `WmiSetBrightness` 没有输出参数：只有缺失输出对象或明确的可选 `ReturnValue` 不存在才继续精确回读；显式非零、空字段、转换失败和 ExecMethod 自身错误仍失败。写入返回不能替代回读确认。

最终版交接时，旧版因上述回读错误不能按 WM_CLOSE 退出。独立 CIM 按 journal 完整身份确认内屏已恢复为 64，确认无黑窗、设置无待修改且记录完整保留后，以 WM_QUIT 结束旧消息循环，执行正常资源释放与工作线程 join，退出码 0。新版启动处理同一份原始 journal，精确恢复确认后自动清除；独立 CIM 再核对仍为 64。没有强杀或手工删除恢复记录，没有外屏硬件请求。

## 91C 阶段验证与证据

最终构建通过格式检查、全目标全 feature Clippy、44 项库测试、9 项桌面程序测试和 4 项恢复集成测试，共 57 项常规测试。另显式通过 WMI 只读路径反例；桌面只读命中、原生监听生命周期和用户真实侧键双击在同轮诊断构建中通过。生命周期覆盖全局鼠标与桌面键盘各三次启动/停止，没有注入输入。

最终 EXE 的 Type-C 隔离窗口消息回归通过：两套键盘/鼠标录入、完整按键名称、独立单双击、启用开关、重复组合拒绝、取消录入与重启持久化，以及三组既有启动/主题/关于回归。截图已核对真实控件文字和布局；没有把消息录入当作物理按键，也没有把本轮启动恢复当作完整三屏熄亮验证。HDMI 工作屏未测试。

本地证据位于工作区 `.local/desktop-trigger-fix-20261103/`：`physical-side-button-fixed.log`、`wmi-path-red.log`、`wmi-path-green.log`、`final-build-wmi-path.log`、`two-trigger-ui-wmi-final/results.json`、`startup-ui-wmi-final/results.json` 和 `delivery.json`。这些是开发阶段原始证据；对应修复已归入 v0.4.0，当前发行结果以 VALIDATION 为准。
